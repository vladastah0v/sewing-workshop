## К Агенту 1 (ядро: `src/types`, `src/lib`, `src/components/ui`)

1. **Иконки `users`, `award`, `truck`, `wallet`, `pencil`** — `IconName` в `src/types/content.ts`.
   Нужны на страницах «О мастерской» (преимущества мастерской, состав команды) и
   «Как мы работаем» (оплата, доставка). Существующий реестр закрывает швейную тематику
   и контакты, но не эти смыслы; подставлять `sparkle`/`check` во все слоты подряд —
   набор перестаёт читаться.
   *Обход:* использую `star`, `shield`, `clock`, `check` из текущего реестра.

2. **`src/lib/seo.ts` — общий модуль JSON-LD** (`localBusinessJsonLd`, `serviceJsonLd`,
   `aggregateRatingJsonLd`). Сейчас микроразметку страниц собираю в `src/content/seo.ts`,
   потому что `src/lib/**` — не моя зона. Логика нужна и Агенту 2 на главной
   (`ReviewsSection.averageRating`, `MapSection`), то есть будет продублирована в двух зонах.
   *Обход:* держу builders в `src/content/seo.ts`, экспорт именованный — переезд в `lib` будет
   механическим (сменить путь импорта).

3. **`SITE_NAME` / контакты в `LocalBusiness`.** `SITE_NAME = 'Швейная мастерская'` и
   `CONTACTS.organizationName` дублируют друг друга. В микроразметке нужно одно имя
   организации. Предлагаю оставить источником `CONTACTS` и убрать дубль из `constants.ts`
   либо явно задокументировать, что `SITE_NAME` — только для `<title>`.
   *Обход:* в JSON-LD беру `CONTACTS.organizationName`.

4. **`ContactInfoData.legalEntity`** (название юрлица, ИНН, ОГРН) — `src/types/content.ts`.
   Требуется на странице политики конфиденциальности: оператор персональных данных
   по 152-ФЗ должен быть назван реквизитами, а не торговым именем. В модели такого поля нет.
   *Обход:* в тексте политики стоит явная пометка-заглушка «реквизиты уточняются»
   (открытый вопрос №6 в `docs/CONTRACTS.md`).

5. **`SeoMeta.keywords` не нужен, а `SeoMeta` без `h1`** — `src/types/content.ts`.
   Для страниц услуг Title и H1 по SEO различаются (Title с гео и ценой, H1 короткий).
   Сейчас H1 приходится хранить отдельно от `seo`.
   *Обход:* H1 беру из `Service.title`, `seo.title` использую только для `<title>`.

## К Агенту 1 (сборка)

8. **`package-lock.json` рассинхронизирован с `package.json`.** В корневой записи лока
   нет `@eslint/eslintrc`, хотя в `package.json` он объявлен в `devDependencies`.
   Из-за этого любой `npm run …` дописывает строку в лок — файл показывается изменённым
   у всех трёх агентов и даёт лишний конфликт при мерже. Нужен один `npm install`
   владельцем и коммит обновлённого лока.
   *Обход:* после каждого прогона проверок откатываю файл через `git checkout -- package-lock.json`.

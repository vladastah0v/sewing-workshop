## К Агенту 1 — `src/types/ui.ts`, `src/types/api.ts`

1. **Сделать `LeadRequest.name` необязательным (или добавить `name?: string`)** — `src/types/api.ts`,
   плюс снять проверку имени в `validateLead` для заявок без него.
   Почему: вариант `RequestForm variant="inline"` по контракту (п.5.5) рендерит только телефон и
   согласие — поля имени в нём физически нет, а `name` обязателен и проверяется на 2–80 символов.
   Временно: inline-заявка уходит с именем-заглушкой `«Клиент с сайта»`, оно видно владельцу в
   Telegram. Это данные, которых пользователь не вводил, — в проде так оставлять не стоит.

2. **Добавить `defaultMessage?: string` в `RequestFormProps`** — `src/types/ui.ts`.
   Почему: `CalculatorForm` показывает предварительную вилку цены и тут же предлагает оставить
   заявку, но передать расчёт во вложенный `RequestForm` нечем — менеджер получает заявку без
   контекста и звонит уточнять то, что человек уже выбрал.
   Временно: расчёт остаётся только на экране, в заявку не попадает.

3. **Добавить `disabled?: boolean` в `ConsentCheckboxProps`** — `src/types/ui.ts`.
   Почему: контракт п.6.5 требует блокировать поля на время `submitting`. Все поля формы
   блокируются, а чекбокс согласия — нет, потому что пропса нет.
   Временно: чекбокс остаётся активным во время отправки; отправка всё равно защищена
   проверкой `if (submitting) return`.

4. **Добавить `error?: string` (или `hint`) в `RatingProps`** — `src/types/ui.ts`.
   Почему: оценка в `ReviewForm` — обязательное поле, `validateReview` возвращает для неё ошибку,
   но `Rating` не умеет её показывать и не связывает текст ошибки с контролом через
   `aria-describedby`, как это делает `FormField`.
   Временно: подпись, звёздочка обязательности и текст ошибки нарисованы рядом с `Rating`
   вручную в `ReviewForm.tsx`; связи по `aria-describedby` нет.

## К заказчику (через Агента 1, контракт п.11)

5. **Коэффициенты калькулятора** — `src/components/forms/CalculatorForm.tsx`.
   Почему: расчёт строится на множителях за сложность (1 / 1,3 / 1,8), срочность (1,5) и на
   ширине вилки (×1,6). Эти числа взяты как рабочая заглушка — реальных данных по
   ценообразованию нет (открытый вопрос п.3 контракта: полный список услуг с ценами).
   Временно: цифры помечены в коде как временные, на экране стоит дисклеймер
   «расчёт примерный и не является офертой».

## Инфраструктура (без изменений в чужих файлах)

6. **Хранилище загруженных фото.** `POST /api/uploads` кладёт файлы во временный каталог ОС
   (`os.tmpdir()`) с TTL 6 часов и отдаёт превью через `GET /api/uploads?id=…`.
   Для одного инстанса Node этого достаточно, при деплое в serverless или в несколько реплик
   файл может не найтись при следующем запросе — потребуется S3 или диск заказчика.
   Контракт ответа (`UploadResponseData`) при замене хранилища не меняется.

7. **Лимит по IP** (`src/lib/rate-limit.ts`) считает отправки в памяти процесса.
   При нескольких репликах лимит станет «на реплику» — нужен Redis. Интерфейс
   `checkRateLimit()` под замену уже рассчитан.
